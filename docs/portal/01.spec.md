# Specification - GameWorks OAK

## 概要
GameWorks OAK のポータルサイト（GitHub Pages）。
T.I.OAK が開発中の複数のゲームを紹介し、各ゲームへの入り口となる。

## デザインコンセプト
- プレミアム感: ダークモードを基調とし、ネオンカラーやグラデーションを効果的に使用。
- 没入感: ガラスモフィズム、微細なアニメーション、ホバーエフェクトを採用。
- カードデザイン: 
  - 各ゲームを象徴するコンセプトアート（`.game-img`）を背景に配置。
  - タイトル・ロゴのオーバーレイ: タイトル（ロゴまたはテキスト）を画像の上部・中央に重ねて表示。視認性向上のため強力なドロップシャドウを適用。
  - ステータスバッジ: `COMING SOON` 等のバッジを画像内の右下に配置。
  - カプセル型のタグ（`PvP`、`ローグライク` 等）により特徴を明示。
- レスポンシブ: PC、タブレット、スマートフォンすべてで最適化。

## 技術スタック
- Environment: `Node.js` (`Vite`)
- Deployment: `GitHub Actions` (Target: `gh-pages` branch)
- Structure: `HTML5` (Semantic HTML), `CSS3` (Vanilla CSS, Custom Properties), `JavaScript` (Vanilla JS, ES Modules)
- Assets: `SVG` (Portal Logo), Remote Project Assets

## データ構造とセマンティック定義
ポータルサイトの各要素は、メタデータ（JSON）で定義された「型（Type）」に基づき、一貫したデザインと挙動を維持します。インラインスタイルによる個別指定は原則禁止し、以下のセマンティックな定義に従います。

### 1. アクションボタン (`button.type`)
ユーザーがプロジェクトに対して実行可能なアクションの状態を定義します。
- `published`: 公開中。プレイ可能。アクセントカラーで強調。
- `pending`: 公開停止中・準備中。ボタンは無効化（Disabled）され、控えめな表現に。

### 2. ラベルバッジ (`badge`)
プロジェクトに関する補足情報を定義します。`badge.type` はバッジの基本種別を表し、期間限定の注目演出は `badge.featuredUntil` で付加します。

- `type: "info"`: 通常情報（例：`v1.0` 公開中、〇月公開予定）。バッジを表示する場合の標準種別。
- `type: "none"`: バッジを表示しない。

`featuredUntil` は `YYYY-MM-DD` 形式の日付文字列で指定します。現在日付が `featuredUntil` 以下の場合、`info` バッジに注目属性を付加し、強調デザインや控えめな反射アニメーションなどを適用できます。期限切れ、未指定、不正な日付の場合は通常の `info` バッジとして扱います。正確な時刻指定は行わず、ポータル表示上の大まかな注目期間を表す用途に限定します。

### 3. ロゴ表示規格 (`logo.type`)
プロジェクトロゴの表示方法と、アセット制作の基準となる規格を定義します。

| 型 | 表示の振る舞い | 用途 |
| :--- | :--- | :--- |
| `standard` | `300px` × `140px` の長方形枠内に収めて表示。 | ロゴデザインが完成している場合。 |
| `text` | カード上部・中央にタイトルをテキストで表示。 | ロゴ未完成時、またはテキスト表現。 |

- 表示ルール（standard）:
    - 拡大なし: アセットが 横幅 300px・高さ 140px より小さい場合は、原寸で「左右中央・上寄せ」に配置する。
    - 縮小あり: アセットが 横幅 300px または 高さ 140px より大きい場合のみ、枠内に収まるよう縦横比を維持して縮小し、「左右中央・上寄せ」に配置する。
    - デザイナーへのガイドライン: ロゴ制作者は「300x140 の枠内で最も美しく見える（上寄せを考慮）」ように、必要に応じて周囲に余白を含めたアセットを制作する。

### 4. メインビジュアル規格 (image)
カードの背景画像に関する描画仕様を定義します。
- 描画ロジック: 元画像のアスペクト比に関わらず、カード内の指定領域を完全に埋めるように描画する。
- 変形の禁止: アスペクト比を維持して描画し、画像をストレッチさせてはならない。
- 配置とトリミング: object-fit: cover および object-position: center を適用し、中央を基準に過不足分をクリップして表示する。
- 解像度対応: 高解像度ディスプレイ（DPR 2.0以上）での鮮明さを維持するため、十分な解像度のソース取得を考慮した実装とする。

## 構成
- Header: 
  - インラインロゴ: `Inkscape` で調整されたパスデータを `index.html` に直接インライン展開。CSS 変数や外部ファイルに依存せず、いかなる環境でも 100% 正確な造形を維持する。
  - Shrinking Effect: ユーザーのスクロールに合わせてヘッダー（`100px` → `70px`）とロゴ（`60px` → `40px`）がスムーズに縮小し、コンテンツの閲覧エリアを広げる。
  - Cog Rotation: スクロール量に連動してロゴ内のギア（歯車）が回転する。SVG の `rotate` 属性と幾何学的な中心座標（Cog 1: `110.72, 23.20` / Cog 2: `100, 100`）を使用することで、軸のブレがない精密な回転を実現。2つのギアは噛み合わせを考慮し、逆方向に回転する。
- Hero: ブランドイメージを象徴するキャッチコピー。
- Games Section: 
  - `public/data/project_list.json` (マニフェスト) と各ゲームプロジェクトが公開する `data/project_info.json` に基づき動的に生成されるカード。
  - プロジェクトの追加・更新: マニフェストに対象プロジェクトを追加し、各ゲーム側の標準データを更新することで反映される。
  - ロゴ表示: `logo.type: standard` の場合、指定された `SVG`/画像を `fetch` して規定のキャンバス規格（`300x140`, `scale-down`）で表示。`text` の場合はタイトル文字列を装飾して表示。
  - ボタンとバッジ: メタデータの `type` 指定に基づき、公開状態や情報の重要度が自動的にスタイルに反映される。
  - Update History: 各カードの右下に配置されたテキストリンクから、各プロジェクトの `update_history.json` を取得・表示可能。
- Update History Modal:
  - 各プロジェクトの `update_history.json` を非同期で取得して表示。
  - 構造: `modal-header` と `modal-body` を分離し、タイトルと閉じるボタンを上部に固定。
  - デザイン: ガラスモフィズムを採用したプレミアムかつインダストリアルなデザイン。派手な装飾を排し、情報の読みやすさを最優先。
- Footer: シンプルなコピーライト表示。
