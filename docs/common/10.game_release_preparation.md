# 公開準備手順

## 開始条件

オーナーが公開すると判断したゲームを対象とする。
[環境構築](09.game_setup.md)の後も設計・開発を継続しながら実施できる。
公開判定を行う時期や予告期間の長さは一律に定めない。
公開予告は公開準備に含まれる作業である。

## 実施項目

1. 公開すると判定した時点で、いつゲームを公開する予定にするかをオーナーと調整する。担当者だけで予定時期を決めない。合意した予定時期と、予告に表示する文言を確認する。
2. GitHub Pagesなどの公開環境、Viteの`base`、ビルド成果物、デプロイ先・起動条件・権限を整える。共通部checkoutと相対importの解決を含め、[共通ライブラリの公開運用](90.common_library.md)に一致させる。
3. ゲーム側に`public/data/project_info.json`、`public/data/update_history.json`、紹介用のロゴ・画像を用意する。タイトル、説明、タグ、多言語表示、素材パスを確認する。形式と寸法は[共通構成](04.common_structure.md#2-標準データ提供インターフェース)に従う。
4. 合意した公開予定時期を`project_info.json`の`badge.content`へ記載し、`badge.type`を`info`にする。`button.content`は`COMING SOON`等の予告文言、`button.type`は`pending`とし、`button.url`にはゲームの公開先を設定する。
5. ゲーム側の所定のフェーズ運用・デプロイ手順で紹介JSONと素材を公開し、公開URLから取得できることを確認する。`project_info.json`へ格納しただけではポータルへ反映されない。v0期間の更新履歴は空配列`[]`を維持する。
6. ポータルのアプリリスト`GameWorksOAK/public/data/project_list.json`への登録状況を確認する。登録は基本的にオーナーが対応するため、未登録なら必要なゲームID・タイトルを伝えて対応を依頼し、完了の連絡を待つ。ゲーム開発者がアプリリストを修正することは責務外である。
7. オーナーから登録完了の連絡を受けるか、アプリリストが対応済みであることを読み取りで確認し、登録作業の完了を記録する。ポータルで確認できる場合は、紹介文・ロゴ・背景・公開予定・無効ボタンの表示も確認する。必要なゲーム側作業と登録作業の完了を確認できたら、公開準備を完了とする。

公開準備後も、公開に向けた開発・検証を継続する。
ゲーム本体の公開対象版、必要なオーナー検証、残る作業を整理し、[ゲーム公開手順](11.game_release.md)へつなぐ。

## 公開予告の表示と反映

CanWeBecomeHeroesの`public/data/project_info.json`では、次の組合せで予告を表示する。

| 項目 | 例 | 役割 |
| --- | --- | --- |
| `badge.content` | 日本語「11月公開予定」、英語「Coming November」 | オーナーと調整した公開予定時期を表示する。 |
| `badge.type` | `info` | 情報バッジとして表示する。 |
| `button.content` | `COMING SOON` | 予告中であることを示す。 |
| `button.type` | `pending` | ポータルのプレイボタンを無効化する。 |

この月や文言は記載例であり、各ゲームの予定はオーナーと調整する。
公開予定の表示による自動公開・自動切替はない。`featuredUntil`も任意の注目表示期間であり、公開日設定ではない。

ポータルはアプリリストの`id`から`https://t-i-oak.github.io/{id}/`を組み立て、紹介JSON・素材・更新履歴を取得する。
そのため、ゲーム側のデータ公開とポータル側のアプリリスト登録の両方が必要になる。
`pending`はポータルからの遷移を止める設定であり、ゲームURLへの直接アクセスを制限しない。
公開予告のためにゲーム本体を別の成果物に分離することは、この手順の要件にしない。

## 完了条件

- 公開予定時期をオーナーと調整し、その結果を`project_info.json`へ反映している。
- 公開環境、標準JSON、紹介素材を整え、公開先から取得できる。
- ポータル側のアプリリストへの登録作業が完了したことを、オーナーの連絡または対応済みリストの確認で把握している。

JSONの格納だけ、または登録依頼だけでは完了としない。
ゲーム開発者はゲーム側の作業と登録完了の確認を担当し、ポータルのアプリリストを修正しない。
