# Multi-Language (i18n) Library Specification

## 役割
GameWorks OAK ポータルおよび各ゲームアプリ間で「言語設定」をシームレスに同期・共有し、ローカルやリモートの JSON リソースを多言語に自動展開する機能を提供します。

---

## 共有言語設定
言語設定は、個別ゲームID（`gameId`）の領域から独立したドメイン共通の保存キー（`'gameworks_portal_lang'`) で `localStorage` に直接保存されます。
これにより、ポータルサイトでの言語選択（日本語 ⇄ English）が、全ゲームアプリに対してもシームレスかつ即座に反映・共有されます。

---

## 初期言語とフォールバック言語の分離仕様

ユーザー体験（UX）を最適化し、かつ多言語リソースの網羅的フォールバックを可能にするため、本ライブラリでは**「初期言語」と「フォールバック言語」を明確に分離**して管理・処理します。

*   **初期言語 (言語未選択時のデフォルト) : `"ja"` (日本語)**:
    ユーザーが初めてサイトを訪れた際（`localStorage` に言語設定が保存されていない初期状態）に適用される言語です。日本のユーザーをメインターゲットとするため、初期状態では日本語表示を最優先とします。
*   **フォールバック言語 (リソース欠損時のデフォルト) : `"en"` (英語)**:
    現在の選択言語（例: `"ja"`, 将来の他言語）に対応する翻訳テキストが `lang-store` オブジェクト内に定義されていない場合に、最終的に適用されるデータです。アセットの網羅性が高い英語をフォールバック先とします。

---

## サポートする言語コードの規格 (規格マスター)

他のゲームアプリやポータルで、言語識別用のキー（キー名）が混在（例: `"jp"` と `"ja"` の混在）してデータ連携が破壊されることを防ぐため、GameWorks OAK プロジェクト群における多言語対応の言語コードは以下の **ISO 639-1** 規格に厳格に準拠して定義します。

> [!WARNING]
> 国名コード（例: `"jp"`）を言語コードとして使用することは**厳禁**とします。必ず以下の「言語コード」を使用してください。

| 言語コード (Key) | 対象言語 | 表示名 (推奨) | 備考 |
| :--- | :--- | :--- | :--- |
| **`ja`** | 日本語 (Japanese) | `日本語` | `"jp"` は使用禁止。言語未選択時の初期デフォルト言語。 |
| **`en`** | 英語 (English) | `English` | リソース欠損時の最終フォールバック言語。 |
| **`zh`** | 中国語 (Chinese) | `中文` | 将来の拡張用。必要に応じて `"zh-cn"`, `"zh-tw"` と記述。 |
| **`ko`** | 韓国語 (Korean) | `한국어` | 将来の拡張用。 |

各ゲームアプリが提供する言語選択UI（プルダウンなど）は、それぞれのゲームが対応している言語リソースの状況に合わせて、上記テーブルのコードを用いて独自に構築してください。
ライブラリレベルで一元的なリストを提供しないことにより、**「ゲームで対応していない言語がプルダウンに表示され、ユーザーが立ち応生する現象」を完全に回避**しつつ、ドメイン全体での言語設定キーの整合性を完璧に維持します。

---

## アクティブ言語（Active Language）の自動補正仕様 💡

ドメイン共通の言語設定が、**その言語をサポートしていないゲームに持ち込まれた際のプルダウンや表示の不整合**を防ぐため、本ライブラリはメモリ上での「アクティブ言語」の自動解決・補正機能を備えています。

### 解決される問題（ねじれ現象の回避）
1. ユーザーが中国語（`zh`）対応のゲーム A で `zh` を選択すると、グローバル設定（`localStorage`）が `zh` になります。
2. ユーザーが `zh` 非対応のゲーム B（`ja`, `en` のみをサポート）に移動した際：
   *   **生の設定（localStorage）は `zh` のまま温存**します（ゲーム A に戻ったときに設定が破壊されるのを防ぐため）。
   *   ゲーム B の内部では、アクティブ言語が自動的に **`en`**（英語）に解決され、リソースは英語で展開されます。
   *   ゲーム B の言語選択プルダウンも、不整合を起こさず美しく **`English`** が選択された状態で自動初期化されます。

### アクティブ言語のフォールバック解決フロー
グローバル言語コード（`getLanguage()`）が、アプリのサポート言語リスト（`supportedLangs`）に含まれていない場合、以下の優先順位でアクティブ言語を解決します。
1. サポート言語リスト内に最終フォールバック先である **`"en"`** があれば、それをアクティブ言語とする。
2. リストに `"en"` も含まれていない場合は、**リストの先頭の言語**をアクティブ言語とする。

## JSON データ仕様 (`lang-store`)

言語ごとの動的テキストは、JSON オブジェクトの中に `"lang-store"` というキーを持つオブジェクトを定義して表現します。
```json
{
  "title": {
    "lang-store": {
      "ja": "こんにちは",
      "en": "Hello"
    }
  },
  "score": 100
}
```

*   **展開ルール**:
    *   システムが `"lang-store"` オブジェクトを走査した際、現在のアクティブ言語コード（例: `"ja"`) に対応する値にオブジェクト自体を置換します。
    *   現在のアクティブ言語コードに対応する値が定義されていない場合は、自動的にフォールバック言語の **`"en"`** の値へとフォールバックします。
    *   上記のデータ構造は、多言語展開後は以下のようにシンプルなプレーンオブジェクトへと変換されます：
    ```json
    // 日本語設定（ja）の場合
    {
      "title": "こんにちは",
      "score": 100
    }
    ```

## API

### `getLanguage(): string`
*   **詳細**: 現在のグローバル言語コード（`localStorage` の生の設定値。例: `'en'`, `'ja'`, `'zh'`) を取得します。
    *   `localStorage` が空（初回ロード時）の場合は、初期デフォルト言語である **`'ja'`** を返却します。

### `getActiveLanguage(): string`
*   **詳細**: 現在のアプリのサポート状況（`supportedLangs`）を反映した、実際に適用すべき「アクティブ言語コード」を返します。
    *   サポート言語リストが未登録、または空の場合は、`getLanguage()` の値をそのまま返却します（後方互換性担保）。
    *   グローバル設定がサポート言語外の場合、リスト内の `'en'` ➔ リストの先頭要素 の優先順位で自動補正します。

### `setLanguage(lang: string): void`
*   **詳細**: `localStorage`（共通キー）に指定された言語コードを保存し、登録されたすべてのリスナーにアクティブ言語の変更を伝播します。

### `onLanguageChange(callback: (activeLang: string) => void): () => void`
*   **詳細**: 言語設定が変更（他ウィンドウ/他タブでの変更も自動監視）され、かつアプリ内での「アクティブ言語」が変化した際に呼び出されるコールバックを登録します。
*   **戻り値**: 購読を解除（Unsubscribe）するためのクリーンアップ関数。

### `setupLanguageSelector(selectorOrElement: string|HTMLSelectElement, supportedLangs: string[], onChangeCallback?: (lang: string) => void): void`
*   **詳細**: `<select>` プルダウン要素に対して、双方向バインディングおよび `<option>` の自動展開をセットアップします。
    *   **オプション自動展開 (必須引数仕様)**:
        `supportedLangs` (例: `['ja', 'en']`、配列の指定が必須) に基づいて、自動的に規格マスターから表示名（`ja`->`日本語`, `en`->`English`等）を解決し、`<select>` 下配の既存オプションをクリアした上で `<option>` を自動構築・挿入します。
    *   **値の初期化と双方向同期**:
        プルダウンの値を `getActiveLanguage()` を通じた補正後のアクティブ言語にセットし、値の変更を自動で `setLanguage` に同期します。また外部で言語が切り替わった場合も、プルダウンの見た目が自動同期されます。
    *   **変更時コールバック**:
        値が変更された際に実行する独自の追加処理（再描画など）を指定できます。

### `expandLanguageResource(jsonObj: any): any`
*   **詳細**: 引数として渡された JSON オブジェクトを再帰的に走査し、内部の `"lang-store"` 要素をすべて現在のアクティブ言語設定に従って置換した新しいオブジェクトを返します。
    *   現在のアクティブ言語が定義されていない場合は、自動的にフォールバック言語である **`'en'`** の値を適用します。
*   **深さの制限**: 探索の深さは **`10`** に固定されており、10 を超えるネストや循環参照が発生した場合はエラー（例外）をスローして処理を安全に終了します。

### `loadJsonWithL10n(url: string): Promise<object>`
*   **詳細**: 指定された外部の JSON ファイルを非同期（`fetch`）でロードし、多言語展開したオブジェクトを Promise として返します。

### `loadJsonWithL10nCached(url: string, forceBypass?: boolean): Promise<object>`
*   **詳細**: キャッシュ（通信データ生JSONのメモリ保持）を利用して非同期ロードし、多言語展開したオブジェクトを返します。初回ロード後はネットワーク通信が完全にゼロになり、超高速でチラつきのない言語切り替えを支えます。

## 使用例

### 1. プルダウンの自動生成・双方向バインド・自動同期 (最も推奨)
HTML 側に空の要素 `<select id="game-lang"></select>` を用意しておくだけで、1行でセットアップできます。
ポータル側でもゲーム側でも、同一のシンプルな方法で利用可能です。

```javascript
import { setupLanguageSelector, loadJsonWithL10nCached } from 'https://t-i-oak.github.io/GameWorksOAK/lib/core/i18n.js';

// プルダウンオプションの自動生成、値の双方向同期、および再描画バインドを1行でセットアップ！
setupLanguageSelector('#game-lang', ['ja', 'en'], renderGameScreen);

async function renderGameScreen() {
    // キャッシュ付きでリソースを取得（言語切り替え時はネットワーク通信は 0）
    const gameData = await loadJsonWithL10nCached('data/game_resource.json');
    document.getElementById('title').textContent = gameData.title;
}

// 初期描画
renderGameScreen();
```

### 2. イベントの単独購読によるリアルタイム再レンダリング (別タブ変更との同期含む)
```javascript
import { onLanguageChange, getActiveLanguage } from 'https://t-i-oak.github.io/GameWorksOAK/lib/core/i18n.js';

// 言語が切り替わった（アクティブ言語が変化した）時に実行
const unsubscribe = onLanguageChange((newActiveLang) => {
    console.log(`言語が ${newActiveLang} に切り替わりました。`);
    updateUI();
});

// 必要に応じて購読解除可能
// unsubscribe();
```

## HTML テンプレート描画

How To Play、ルール説明、モーダル本文など、長めの HTML コンテンツを多言語化する場合は、HTML テンプレート内に `{key.path}` プレースホルダーを記述できます。

```html
<section class="help-section">
  <h3>{help.objective.title}</h3>
  <p>{help.objective.body}</p>
</section>
```

テンプレートに渡すリソースは、既存の `lang-store` 形式をそのまま使用できます。描画時に `expandLanguageResource()` が実行され、現在のアクティブ言語に展開された値で置換されます。

### `renderI18nTemplate(template, resource, options?): string`

テンプレート文字列を受け取り、`{key.path}` を置換した HTML 文字列を返します。DOM への反映は行いません。

```javascript
const html = renderI18nTemplate(helpTemplate, helpResource);
container.innerHTML = html;
```

### `applyI18nTemplate(containerOrSelector, template, resource, options?): HTMLElement|null`

指定した container にテンプレートを単発描画します。`containerOrSelector` には HTMLElement または selector 文字列を指定できます。

```javascript
applyI18nTemplate('#help-container', helpTemplate, helpResource, {
    afterRender: (container) => {
        bindHelpEvents(container);
    }
});
```

container が存在しない場合は warning を出し、`null` を返します。

### `bindI18nTemplate(containerOrSelector, template, resource, options?): () => void`

初回描画を行い、さらに `onLanguageChange()` を購読して、言語変更時に同じ container を自動再描画します。戻り値は購読解除関数です。

```javascript
const unbind = bindI18nTemplate('#help-container', helpTemplate, helpResource, {
    afterRender: (container) => {
        bindHelpEvents(container);
    }
});

unbind();
```

`afterRender(container)` は初回描画後と言語変更後の両方で呼ばれます。HTML 差し替え後のイベント再バインドはここに集約してください。

## テンプレート置換仕様

- `{key.path}` でネストしたキーを参照します。
- 参照値が文字列または数値の場合のみ置換します。
- 値が見つからない場合は `{key.path}` をそのまま残し、既定では warning を出します。
- 置換値は既定で HTML エスケープされます。
- `{raw:key.path}` を使うと、その値だけ HTML エスケープせずに挿入します。
- `options.escape: false` を指定すると、通常の `{key.path}` も HTML エスケープしません。

```javascript
renderI18nTemplate('<p>{help.body}</p>', resource);
renderI18nTemplate('<p>{raw:help.htmlBody}</p>', resource);
renderI18nTemplate('<p>{help.htmlBody}</p>', resource, { escape: false });
```

## テンプレート options

```javascript
{
    escape: true,
    warnOnMissing: true,
    afterRender: (container) => {}
}
```

- `escape`: 置換値を HTML エスケープするかを指定します。既定値は `true` です。
- `warnOnMissing`: 欠損キーや置換不能な値に warning を出すかを指定します。既定値は `true` です。
- `afterRender`: `applyI18nTemplate()` / `bindI18nTemplate()` の描画後に呼ばれるコールバックです。
