# Common Project Structure - GameWorks OAK

## 1. 標準フォルダー構成
すべてのプロジェクトにおいて、予測可能性と保守性を高めるため、以下の基本構造を遵守します。

- docs/: プロジェクトの仕様書、バックログ、更新履歴等のドキュメントを配置します。
    - planning/: 開発プロセス（タスク・計画）を管理します。
        - backlog.md: 恒久的なタスク一覧。
        - dev_*: 開発期間中のみ一時的に作成されるドキュメント（dev_implementation_plan.md, dev_handover.md 等）。これらは開発完了時に削除されます。
- public/: 静的アセットを配置します。
    - assets/: 画像、音声、フォント等のリソース。
    - data/: JSON 形式などのデータファイル。
- src/: 開発用ソースコード（JS, CSS 等）を配置します。
- tests/: テストスクリプト・HTMLを配置します。
    - spec/: 要求仕様書の章構成と厳密に対応させた受入テストを配置します。
        - 命名規則: `[prefix]_[章番号]_[名称].test.js` (例: `portal_01_card_display.test.js`)
    - implementation/: 実装に対するテスト（単体・結合テスト）を配置します。`src/` フォルダと同じフォルダ構成とし、ファイル名は `[元のファイル名].test.js` とします。
- index.html: アプリケーションのエントリーポイント（ルート直下に配置）。
- package.json / vite.config.js: プロジェクトの構成ファイル。Vite を標準のビルド・開発ツールとして使用します。

## 2. 標準データ提供インターフェース
ポータルサイトとの連携およびプロジェクト間の整合性を保つため、各プロジェクトは以下の標準パスで情報を公開します。

### ベースURL
`https://t-i-oak.github.io/{ProjectName}/`

### 公開データ（標準パス）
各ファイルは、ビルド後のルートディレクトリ（開発時の public/ フォルダ直下）に配置してください。
- data/project_info.json: ポータルサイト表示用のメタデータ（タイトル、説明、タグ、ボタン設定等）。
- data/update_history.json: ユーザー向けの更新履歴データ。
- assets/logo.svg: プロジェクトを象徴する SVG ロゴデータ（透過背景推奨）。

## 3. Git 管理とプレフィックス
不必要なファイルの混入を防ぎ、ファイルの役割を明確にするため、以下のプレフィックスを持つファイル・フォルダは原則として Git 管理対象外（.gitignore 指定）とします。

- local_: プロジェクトオーナー個人が管理・使用するファイル。
- dev_: 開発期間中（ブランチ運用中）のみ一時的に作成されるファイル。
- tmp_: 作業中に一時的に作成される、即座に削除可能なファイル。

## 4. 外部リソースの参照
共通ライブラリ（GameWorks OAK Common Library）は、以下の GameWorks OAK リポジトリが提供する最新のソースを直接参照してください。

- ライブラリベースURL: `https://t-i-oak.github.io/GameWorksOAK/lib/`
