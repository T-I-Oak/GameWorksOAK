# Common Project Structure - GameWorks OAK

## 1. 標準フォルダー構成
すべてのプロジェクトにおいて、予測可能性と保守性を高めるため、以下の基本構造を遵守します。

- docs/: プロジェクトの仕様書、バックログ、更新履歴等のドキュメントを配置します。
    - planning/: 開発プロセス（タスク・計画）を管理します。
        - backlog.md: 恒久的なタスク一覧。
        - dev_*: 開発期間中のみ一時的に作成されるドキュメント（dev_implementation_plan.md, dev_handover.md 等）。これらは開発完了時に削除されます。
- public/: 静的アセットを配置します。
    - assets/: 画像、音声、フォント等のリソース。
    - data/: JSON 形式などのデータファイル。
- src/: 開発用ソースコード（JS, CSS 等）を配置します。
- scripts/: ビルド補助やメンテナンス用のユーティリティスクリプトを配置します。
- tests/: テストスクリプト・HTMLを配置します。
    - spec/: 要求仕様書の章構成と厳密に対応させた受入テストを配置します。
        - 命名規則: `[prefix]_[章番号]_[名称].test.js` (例: `portal_01_card_display.test.js`)
    - implementation/: 実装に対するテスト（単体・結合テスト）を配置します。`src/` フォルダと同じフォルダ構成とし、ファイル名は `[元のファイル名].test.js` とします。
- index.html: アプリケーションのエントリーポイント（ルート直下に配置）。
- package.json / vite.config.js: プロジェクトの構成ファイル。Vite を標準のビルド・開発ツールとして使用します。

## 2. 標準データ提供インターフェース
ポータルサイトとの連携およびプロジェクト間の整合性を保つため、各プロジェクトは以下の標準パスで情報を公開します。

### ベースURL
`https://t-i-oak.github.io/{ProjectName}/`

### 公開データ（標準パス）
各ファイルは、ビルド後のルートディレクトリ（開発時の `public/` フォルダ直下）に配置してください。

#### 1. data/project_info.json
ポータルサイトのカード表示に使用されるメタデータです。

```json
{
  "title": "プロジェクト名",
  "description": "プロジェクトの短い説明文",
  "tags": ["タグ1", "タグ2"],
  "logo": {
    "path": "assets/logo.svg",
    "type": "standard | text"
  },
  "badge": {
    "content": "表示テキスト",
    "type": "hot | info | none"
  },
  "button": {
    "content": "ボタンテキスト",
    "url": "https://...",
    "type": "published | pending"
  },
  "image": "assets/thumbnail.png"
}
```

- `logo.path`: 各プロジェクトのルートからの相対パス（例：assets/logo.svg）。
- `logo.type`: standard（240x240枠に描画）または text（タイトルをテキスト表示）。
- `badge.type`: hot（注目情報）、info（通常情報）、none（非表示）。
- `button.url`: 遷移先の絶対URL（例：https://.../index.html）。
- `button.type`: published（公開中・有効）、pending（準備中・無効）。
- `image`: カードの背景に使用するメインビジュアルの相対パス（例：assets/thumbnail.png）。
    - アスペクト比: 3:2 を推奨。
    - 推奨解像度: 1200px × 800px 以上。
    - 注意事項: 閲覧環境により端がトリミングされる可能性があるため、主要な要素は中央に配置すること。

#### 2. public/data/update_history.json
プロジェクトの更新履歴を管理する JSON ファイル。開発サイクル（ブランチ）の完了時に最新の内容を追記します。

- バージョン表記: プロジェクト全体のバージョン（`package.json` 等）は Semantic Versioning（x.y.z）で管理しますが、本ファイル内では Minor 単位（x.y 形式）で記載します。Patch レベルの更新内容は Minor 単位の履歴として集約し、Patch 番号は記載しません。
- 記載順: 最新のアップデート内容が配列の先頭に来るよう、降順（新しい順）で記載すること。
- 記載内容: ユーザー体験（UX）に直接関わる内容のみを記載すること。
    - 内部的な作業（テストの追加、リファクタリングそのもの等）の記載は禁止。
    - 性能向上の場合は、作業名ではなく「初期読み込み時間の短縮」「描画の滑らかさの向上」等、具体的に何が改善されたのかを記述すること。
    - UXに関わる変更が一切ないバージョンに限り、例外的に「内部改善」という表記を許容する（詳細の記載は不可）。

```json
[
  {
    "version": "1.1",
    "date": "2026-05-15",
    "content": [
      "新機能の追加",
      "バグ修正"
    ]
  }
]
```

#### 3. assets/logo.svg
プロジェクトを象徴する SVG ロゴデータ（透過背景推奨）。

## 3. Git 管理とプレフィックス
不必要なファイルの混入を防ぎ、ファイルの役割を明確にするため、以下のプレフィックスを持つファイル・フォルダは原則として Git 管理対象外（`.gitignore` 指定）とします。

- `local_`: プロジェクトオーナー個人が管理・使用するファイル。
- `dev_`: 開発期間中（ブランチ運用中）のみ一時的に作成されるファイル。
- `tmp_`: 作業中に一時的に作成される、即座に削除可能なファイル。
