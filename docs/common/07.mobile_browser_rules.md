# Mobile Browser Rules - GameWorks OAK

GameWorks OAK のゲームは、PC だけでなく iPad / Android タブレット / スマートフォンのブラウザ上でも、ゲームとして安定して操作できる必要があります。
本書は、モバイル・タブレットブラウザでブラウザ標準操作とゲーム操作が衝突しないようにするための共通ルールです。

## 0. 適用区分

- `MUST`: すべてのゲームで守る必須ルール。
- `MUST WHEN`: 条件に該当する場合に守る必須ルール。
- `SHOULD`: 原則として採用する推奨ルール。採用しない場合は、同等の安定性を別の方法で担保します。

## 1. Viewport

- MUST: HTML には次の viewport を指定します。
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
  ```
- MUST: ゲームの画面ルートは `100vh` だけに依存せず、`100dvh` を併用します。
  ```css
  height: 100vh;
  height: 100dvh;
  ```
- MUST: 画面全体を固定する領域では、Safari の上部タブやアドレスバーによる表示領域変化を考慮し、実表示領域に追従する `100dvh` を優先します。

## 2. Page Scroll

- MUST: ゲーム画面全体では、ブラウザのページスクロールを発生させません。
- MUST: `html`, `body`, 画面ルート、ゲームコンテナなどの最上位領域は `overflow: hidden` を基本とします。
- MUST WHEN: 説明文、設定、履歴、リザルトなど、スクロールが必要な内容は明示的な内部スクロール領域に閉じ込めます。
- MUST WHEN: 内部スクロール領域は `overflow-y: auto` とし、親コンテナには安定した高さ制約を与えます。

## 3. Game Input Area

- MUST WHEN: canvas / map / board など、スワイプ、ドラッグ、ピンチをゲーム操作として使う領域には `touch-action: none` を指定します。
- MUST WHEN: iPad / iPhone Safari で長押し選択や callout 表示が操作を妨げる領域には、次を指定します。
  ```css
  user-select: none;
  -webkit-user-select: none;
  -webkit-touch-callout: none;
  ```
- MUST WHEN: Pointer / touch / wheel event をゲーム操作として扱い、ブラウザ既定動作を抑止する必要がある場合は、listener を `{ passive: false }` で登録します。
- MUST WHEN: `{ passive: false }` で登録した event では、必要なタイミングで `preventDefault()` を呼び、ページスクロール、ブラウザズーム、コンテキストメニューなどに操作を奪わせないようにします。

## 4. Safe Area

- MUST WHEN: ヘッダー、固定ボタン、画面端の HUD など、端末の safe area の影響を受ける位置に UI を配置する場合は、`env(safe-area-inset-*)` を考慮します。
- MUST WHEN: iPad / iPhone Safari では、上部タブやブラウザ UI によって画面端の要素が隠れないか確認します。

## 5. Overlay / Modal / Tutorial

- MUST WHEN: 画面全体に重ねる overlay、modal、tutorial mask は、必要以上に `100vw` / `100vh` 固定へ依存しないようにします。
- SHOULD: ゲーム画面内に閉じる overlay は、管理対象コンテナを基準に `position: absolute` または `position: fixed` と `inset: 0; width: 100%; height: 100%;` を優先します。
- MUST WHEN: overlay の中で縦方向に収まりきらない内容は、overlay 全体または内部コンテナでスクロールさせ、画面外に操作不能なボタンを出さないようにします。

## 6. Responsive UI Scaling

`transform: scale()` は表示を拡縮しますが、レイアウト上の寸法は変えません。表示座標と内部座標の違いを関連機能が考慮しないと、ドラッグ、独自の当たり判定、ツールチップなどに位置の不整合が生じます。また、一律の縮小は文字の可読性や操作対象の大きさを損なう場合があります。本規定は、拡縮に伴う表示・レイアウト・座標処理の不整合と、可読性・操作性の低下を防ぐためのものです。

- SHOULD: レスポンシブ対応では、CSS 変数などを使った寸法、余白、フォントサイズ、配置、内部スクロールの調整を基本とします。
- MUST WHEN: 表を含むダイアログ・モーダルなど、内部の配置関係や比率を維持するために scale を使う場合は、その必要性と適用範囲を仕様に明記し、以下の条件を満たします。UI 全体を拡縮する場合も同じ条件を適用します。
    - 対応する画面サイズと倍率の範囲で、文字の可読性とボタンなどの操作性を維持すること。維持できない場合は、縮小を続けず、配置や内部スクロールなどを調整すること。
    - 外側のレイアウト、スクロール範囲、関連 UI の配置を、拡縮後の表示と整合させること。
    - 拡縮する機能は、関連機能へ与える座標・寸法・配置の影響を管理すること。
    - 座標・寸法を扱う機能は、対象や祖先要素に scale が使われている可能性を考慮すること。新規機能の追加・既存機能の変更でも、この前提を確認すること。
    - 適用範囲、倍率の管理責務、使用する座標系と変換方法を仕様に明記すること。必要な座標変換は共通化し、各機能での独自補正、固定倍率への依存、親子の拡縮による意図しない倍率の重複を避けること。
- 補足: 演出、押下フィードバック、アニメーションなど、一時的な視覚効果としての scale は許可します。その場合も、既存の拡縮処理との干渉や関連機能への影響を確認します。

## 7. Audio Activation

- MUST WHEN: 音声を使用するゲームは、`window.AudioContext || window.webkitAudioContext` を使い、Safari 系ブラウザでも AudioContext を作成できるようにします。
- MUST WHEN: AudioContext の起動や resume は、ブラウザの自動再生制限に従い、正規のユーザージェスチャ後に行います。
- SHOULD: ページ復帰や一時停止後に音声が `suspended` になる可能性を考慮し、必要に応じて次のユーザージェスチャで resume を再試行します。

## 8. Implementation Pattern

画面全体を固定し、必要な領域だけ内部スクロールさせる場合は、次の構造を基本形とします。

```css
html,
body {
  width: 100vw;
  height: 100vh;
  height: 100dvh;
  overflow: hidden;
}

main {
  width: 100vw;
  height: 100vh;
  height: 100dvh;
  overflow: hidden;
  position: relative;
}

.ScrollArea {
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;
}

.play-viewport {
  touch-action: none;
  user-select: none;
  -webkit-user-select: none;
  -webkit-touch-callout: none;
}
```

Pointer / wheel event をゲーム操作に使う場合は、次の考え方を基本形とします。

```javascript
canvas.addEventListener('pointerdown', handlePointerDown, { passive: false });
canvas.addEventListener('pointermove', handlePointerMove, { passive: false });
canvas.addEventListener('wheel', handleWheel, { passive: false });

function handlePointerDown(event) {
  event.preventDefault();
  // ゲーム操作へ変換する
}
```

## 9. Review Notes

- PC ブラウザだけで確認せず、iPad / Android タブレット / スマートフォン相当の viewport で表示を確認します。
- Safari では上部タブやアドレスバーの状態によって表示領域が変わるため、画面端の固定 UI と主要操作ボタンが隠れないか確認します。
- ゲーム操作領域をスワイプしたとき、ページ全体がスクロールしないことを確認します。
- canvas のピンチ操作をゲーム内ズームやカメラ操作に使う場合、ブラウザ倍率変更が発生しないことを確認します。
- モーダル、How To Play、リザルト、チュートリアルは、短い viewport でも閉じるボタンや次へ進むボタンが操作不能にならないことを確認します。
- scale を使う場合は、対応する画面サイズと倍率で可読性・操作性を確認し、関連機能の座標処理、配置、スクロール範囲が拡縮後の表示と整合することを確認します。
- 音声を使うゲームでは、初回タップ後に SE / BGM が開始できること、ページ復帰後に必要な音声が再開できることを確認します。
