# ゲーム公開手順

## 開始条件

[公開準備](10.game_release_preparation.md)で公開予定の反映とポータル一覧登録の完了が確認され、ゲーム公開に必要な開発・検証が完了していることを確認する。
予告期間の長さは規定しない。ゲームを公開する判断と、各開発タスクの終了承認は区別する。

初回のゲーム公開作業には、オーナーからの「ゲームを公開する指示」と「Major（メインバージョン）をv0からv1へ更新する明示指示」の両方が揃ってから着手する。
公開準備に進むための公開判定や予定時期の合意だけを、これらの指示として扱わない。
指示が不足している場合は不足内容をオーナーへ確認し、公開作業を始めない。v0のままゲームを公開してはならない。
公開後の更新でも公開対象はv1以降とし、追加のMajor更新はオーナーの明示指示がある場合だけ行う。

## 実施項目

1. 公開するゲームのブランチ・コミット・バージョン、公開URL、デプロイ対象を確認する。計画・実装・レビューの成果物と、オーナー検証の判断・対応・明示保留を照合する。公開を妨げる未解決事項があれば解消してから進む。
2. 実装報告に対象テスト・全テスト・本番ビルドのコマンドと結果があることを確認する。共通部の変更などで検証対象が変わった場合は必要な検証を再実行する。
3. 初回公開では明示指示に基づき実装でv1へ更新し、バージョン設定とゲームの確認画面を一致させる。公開対象がv0なら公開を進めない。バージョン更新は[ワークフロー](03.workflow_guide.md#1-バージョン管理)に従い、公開指示だけをMajor更新指示と解釈しない。
4. v1以降の公開版として利用者向けの変更を`update_history.json`へMinor単位で整理し、[共通構成](04.common_structure.md#2-標準データ提供インターフェース)に従う。公開準備中のv0期間は空配列を維持するが、v0をゲーム公開の対象にはしない。公開のための修正が必要なら、マージ中に変更せず実装へ戻す。
5. マージ着手前に[共通ライブラリの公開状態](90.common_library.md#公開状態の確認)を所定の6コマンドで確認する。共通部の必要な変更は、共通部担当による`master`へのマージ・pushが先に完了している必要がある。不合格・未確認なら解消を待つ。
6. [フェーズ作業手順](03.phase_workflow.md)に従い、マージ対象リポジトリ全体の`dev_`・`tmp_`・`phase_`を安全確認して削除・再走査し、削除を含む変更をコミットして`master`へマージする。
7. push直前にも共通部の公開状態を確認し、ゲームの`master`を`origin/master`へpushする。ローカルとリモートのコミットID一致を確認する。マージ開始の指示はpushを含み、追加承認は不要である。失敗時は結果を保持して調査し、force pushしない。
8. 合意したデプロイの完了を確認する。Gitのpush成功だけで公開成功とは扱わない。ビルド対象コミット・共通部参照・転送先が確認した版と一致することを確かめる。
9. 公開URLを直接開き、入口、読み込み、主要なゲーム操作、素材、バージョン表示を確認する。対応端末・ブラウザの確認はプロジェクトの仕様と検証項目に従う。
10. ゲームの動作確認後に`project_info.json`の`button.type`を`published`へ切り替え、遷移先URL・ボタン文言・バッジを公開中の内容にする。`badge.type`は`info`、`badge.content`の基本形式は「○月○日 vX.X公開！」とし、実際の公開日とMajor.Minorを記載する（例：`11月1日 v1.0公開！`）。Patchは含めない。オーナーが明示的に異なるバッジを指示した場合は、その指示を優先する。必要なメタデータ更新も実装・レビュー・マージの規約で公開し、ポータルでゲームへの遷移と表示、更新履歴を確認する。

ポータルはゲーム側の標準JSONを取得するため、予告登録済みのゲームは通常、一覧へ再登録する必要はない。

公開時のバッジを設定するときは、強調表示の期間をオーナーへ確認する。
担当者判断で期間を固定したり、既存ゲームの終了日を流用したりしない。
合意した終了日を`badge.featuredUntil`へ`YYYY-MM-DD`形式で設定する。
強調しない指示の場合は、この項目を省略する。未回答を強調不要と解釈しない。
終了日は当日を含み、閲覧端末のローカル日付で判定される。期限後は通常のバッジ表示となり、文言は残る。
詳細は[標準データ提供インターフェース](04.common_structure.md#2-標準データ提供インターフェース)を参照する。

一覧の追加・修正が必要な場合は共通部担当へ依頼する。
デプロイ失敗や公開先の不具合は、確認できた状態・原因・必要な対応を報告し、公開完了として扱わない。

## 完了条件

- 公開対象のコミットとデプロイ結果が確認できる。
- 初回公開は公開指示とv1へのMajor更新指示に基づいて実施され、公開対象の設定・画面表示がv1以降で一致している。
- 公開URLで対象版が動作し、主要操作と素材・バージョン表示が確認できる。
- ポータルが公開中を示し、ゲームへ遷移でき、更新履歴が規約に一致する。
- バッジが「○月○日 vX.X公開！」の基本形式、またはオーナーが明示した形式で表示されている。
- 強調表示の期間をオーナーに確認し、合意した終了日を`badge.featuredUntil`へ設定している。強調しない指示の場合は省略している。
- 検証結果と残る事項が記録されている。マージ・push結果と引継ぎ書削除の報告はフェーズ作業手順に従う。
