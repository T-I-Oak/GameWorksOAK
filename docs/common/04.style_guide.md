# Common Style Guide - GameWorks OAK

## 1. 保守性の原則
デグレードを防ぎ、長期的なメンテナンスを可能にするため、以下のルールを厳守します。

- !important の禁止: 詳細度を制御し、予期せぬスタイルの上書きを防ぐため、原則として使用を禁止します。
- inline-style の制限: HTMLへの直接記述は避け、CSSファイルで管理します。ただし、JavaScriptによる動的な値の計算（座標、進捗率など）が必要な場合に限り、例外として許可します。

## 2. 意味に基づいたクラス設計
役割を明確にするため、以下の階層構造でクラスを定義します。種別以外の4つには特定の接頭辞を付与します。

### テーマ (theme-)
アプリケーション全体の配色や雰囲気を決定します。基本的に最外周の要素に定義します。
- 例: .theme-dark, .theme-light, .theme-neon

### 機能 (UpperCamelCase)
要素の形状、レイアウト、構造を決定します。質感（見た目）とは切り離した「仕組み」を定義します。接頭辞は付けず、大文字で開始します。
- 例: .Button, .Container, .Grid2Col

### 質感 (texture-)
要素の表面的な見た目（色、光沢、影など）を決定します。テーマと組み合わせて具体的なデザインが完成します。
- 例: .texture-gold, .texture-glass, .texture-warning

### 状態 (state-)
要素の現在の動的な状態を示します。
- 例: .state-disabled, .state-active, .state-selected, .state-primary

### 種別 (lower-case)
その要素が「何であるか」という固有の名称を示します。接頭辞は付けず、必ず小文字で開始します。
- 例: .title, .achievement-card, .logo, .user-name

## 3. 実装の考え方
スタイルを定義する際は、「何のためにそのクラスを当てるのか」という意味を常に意識してください。機能と質感を分離することで、ボタンの形はそのままに、見た目だけを「金」から「銀」へ変えるといった変更が容易になります。
