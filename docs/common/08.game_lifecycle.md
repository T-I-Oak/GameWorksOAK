# ゲーム開発全体の流れ

## 目的と適用範囲

新しいゲームの開発開始から公開までの作業順序を示す。
各開発タスクの計画・実装・レビュー・マージは、[フェーズ作業手順](03.phase_workflow.md)に従う。
ここで示す環境構築・公開準備・ゲーム公開は、タスクのフェーズ名ではない。

## 作業の流れ

| 順序 | 作業 | 到達点・分岐 |
| --- | --- | --- |
| 1 | [環境構築](09.game_setup.md) | 公開を前提とせず、ローカル開発・テスト・本番ビルドとGit管理ができる。 |
| 2 | 設計・開発開始 | 要求・仕様とバックログを整備し、タスクごとのフェーズ運用で開発する。 |
| 3 | オーナーによる公開判定 | 設計・開発期間中の任意のタイミングで、公開するかを判断する。 |
| 4 | [公開準備](10.game_release_preparation.md) | 公開予定時期をオーナーと調整して紹介JSONへ反映し、公開予告を準備する。基本的にオーナーが対応するポータル一覧登録の完了を確認して終える。 |
| 5 | 公開に向けた開発継続 | 予告中も開発・検証を継続し、ゲーム公開に必要な確認を完了する。 |
| 6 | [ゲーム公開](11.game_release.md) | 初回は公開指示とv1へのMajor更新指示が揃ってから着手する。v1以降の対象版をデプロイして実動作を確認し、ポータルを公開中へ切り替える。 |

公開しないと判断した場合は、開発を終了する場合がある。
継続する場合も、公開準備やポータル登録を必須作業にしない。
公開判定を行う具体的な時期や判断事情、予告期間の長さは、この手順では規定しない。

## 規約の読み方と適用時期

- 作業者は[開発理念](01.philosophy.md)、[文書ガイド](02.doc_guide.md)、[ワークフロー](03.workflow_guide.md)、[共通構成](04.common_structure.md)を理解する。
- コード・画面の実装では[コーディング](05.coding_guide.md)、[CSS](06.css_design_rules.md)、[モバイル対応](07.mobile_browser_rules.md)、[共通ライブラリ](90.common_library.md)の各規約を適用する。
- [準拠チェックリスト](99.compliance_checklist.md)は作業段階に対応する項目を確認する。公開データ・素材・デプロイ設定は公開準備で整え、環境構築の完了条件に混ぜない。
- 公開準備の中で、公開予定時期をオーナーと調整し、紹介JSONを公開する。JSONの格納だけでは完了せず、ポータル一覧登録の完了まで確認する。ゲーム開発者はポータル一覧を修正しない。

## 完了条件

ゲーム公開まで進む場合は、各手順の完了条件と公開先での確認結果を満たす。
非公開で終了する場合は、その判断と残る作業をプロジェクトの計画・バックログへ記録する。
タスクのフェーズ終了・引継ぎ・コミットは、公開の判断とは別に既存のフェーズ規約で行う。
