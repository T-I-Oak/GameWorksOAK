# レビュー内のバックログ整理とマージの計画

## 対象

- ブランチは `docs/v1.13-review-merge` とする。実装開始時にバージョン設定を `1.13.0` に更新する。
- 共通ワークフローとフェーズ作業手順を改訂し、共通構成、ゲーム開発全体の流れ、準拠チェックリストなどの関連記述を照合する。旧手順を参照する実行ガイドも、同じ承認順序で運用できるよう整合させる。
- ゲーム、ポータル、共通ライブラリの機能変更は対象外とする。

## 完了条件

- レビュー担当は、未解決の指摘がなくなった時点で、計画、実装結果、バックログの「要望・バグ指摘」を照合する。完了条件を満たした項目は、項目名、既存のIDがあればそのID、完了と判断した根拠をレビュー結果の草案に記載する。一部対応の項目は残作業を示してバックログに残す。削除予定がゼロの場合は「なし」と記載する。
- レビュー結果と削除予定項目を同じ草案で提示し、提示した項目の削除、masterへのマージ、pushについて、オーナーの承認をまとめて得る。訂正があれば草案を修正して再提示する。
- 承認後に、提示した項目の削除を開発ブランチに反映する。一時成果物の整理とコミット、masterへのマージ、push、リモートへの反映確認までを同じレビュー・フェーズ内で行う。独立したマージ・フェーズを廃止する。
- 修正が必要な場合は、レビュー結果と実装への引継ぎ草案を提示する。「オーナー検証」欄の却下・確認済みに伴う削除は、オーナー判断が届いた時点で反映する既存手順に従う。

## 実装・検証方針

- フェーズ判定表、承認、引継ぎ、コミット、マージ・pushと失敗時の扱いを一貫した手順にする。承認待ちの間は、保存済みの引継ぎ書でレビューを継続できるようにする。
- 指摘なし、指摘解消後の再レビュー、実装への差し戻し、承認待ち、草案の訂正、削除対象なし、一部対応、push失敗の各ケースを文書上で確認する。独立したマージ・フェーズを前提とする参照を検索し、差分と関連文書を照合する。
- 実装フェーズで全テストと本番ビルドを実行し、実装報告に結果を記録する。
