# 正式版・仮版の共通公開とポータル参照切替 計画

## 合意内容

- 予定バージョン: 1.17.0。package.json・package-lock.json の更新は初回の実装開始時に行う。
- ブランチ: feature/v1.17-preview-deployment
- 対象領域: 共通仕様、共通ビルド・公開処理、共有文書、ポータル、更新履歴。
- 計画開始と開発内容・ブランチ名は、それぞれオーナーの明示合意を得た。

## 目的とスコープ

ポータルと全ゲームに共通の公開ルールと再利用可能な GitHub Actions ワークフローを用意する。
公開する人が公開パスや正式版・仮版の設定を入力・変更しなくてよい構成にする。

1. 共通ルール、共通ワークフロー、各リポジトリ用の呼び出し設定例を作成する。
2. ポータルを共通ワークフローへ移行する。
3. ポータルの query string による各ゲームの参照先切替を実装する。
4. 既存6ゲームのバックログ「要望・バグ指摘」の先頭に移行作業を追加する。

## 共通公開ルール

| 項目 | 正式版 | 仮版 |
| --- | --- | --- |
| 起動 | master への push | 開発ブランチを選んで手動実行 |
| URL | https://t-i-oak.github.io/{リポジトリ名}/ | https://t-i-oak.github.io/{リポジトリ名}/preview/ |
| gh-pages 内の配置先 | ルート | preview/ |
| 更新方法 | 正式版を更新し仮版を保持 | 仮版を上書きし正式版を保持 |

- ビルドコマンドは npm run build、成果物は dist に統一する。
- 公開パスは共通処理で決定してビルドへ渡す。呼び出し側や実行者に任意の公開先を指定させない。
- 手動実行から正式版を公開しない。正式版は master の push に限定する。
- 許可するイベント・ref と公開先、ビルド時のパスの整合を検証し、不整合なら配置前に停止する。
- 同一リポジトリの公開更新を直列化し、正式版と仮版の同時更新による競合を防ぐ。
- 不要ファイルの清掃は公開対象の範囲に限定する。本番更新でも preview を保持する。
- 共通ライブラリはゲームの隣接位置で参照できるよう checkout し、公開済み master を使用する。
- ポータル自身のビルドは自リポジトリのソースを使い、ゲーム用の隣接配置と区別する。
- 共通ワークフローの参照方法と更新手順を文書化する。ブランチ・タグ・SHAの選定は保守方法と再現性を踏まえて実装で具体化する。
- 通常操作で公開先を取り違えない仕組みを目指す。設定ファイルの意図的な改変まで防ぐ保証とはしない。

## ポータルの参照ルール

| ポータル自身 | query | ゲームの参照先 |
| --- | --- | --- |
| 正式版または仮版 | preview=on なし | 正式版 |
| 正式版または仮版 | preview=on | 仮版 |

- preview=on のときだけ全ゲームの基準URLへ preview/ を付ける。
- 紹介JSON、ロゴ、サムネイル、更新履歴、プレイ先を同じ参照環境へ揃える。
- ポータル自身の project_list.json は、そのポータルの配置先から取得する。
- 言語選択の左に Preview タグを表示する。表示条件は query のみとする。
- JSON取得失敗は既存の簡易表示・プレイ不可の処理を使用する。
- 仮版専用の未公開表示や正式版への自動フォールバックを追加しない。
- 言語切替後も参照環境を維持する。
- project_info.json の相対パス、既存のゲーム自身への絶対URL、外部リンクを区別する。
  自ゲームのURLは参照環境へ揃え、外部リンクを一律置換しない。
  既存の button.type による有効・無効の判定は維持する。
- 標準データのパス表現と解決方法を共通仕様へ明記し、既存ゲームの移行項目に含める。

## 各ゲームの移行バックログ

対象: BurstCascade、GravityFreight、MagicCrystal、CanWeBecomeHeroes、MyPalette、PrismDrift。

- 既存のバックログを保持し、「要望・バグ指摘」の先頭へ追加する。
- 共通処理の master へのマージ・push 完了を依存条件にする。
- 共通ワークフロー呼び出しへの切替、npm run build / dist と公開パスの対応、標準データのURL確認を記載する。
- 正式版・仮版の公開、相互保持、仮版からの読み込みとポータル連携の確認を完了条件に含める。
- このタスクで各ゲームのコードやワークフロー自体は移行しない。
- 兄弟リポジトリへの編集はこのバックログ追加に限定し、各リポジトリのルールと未コミット変更を確認する。
  書き込み権限が不足する場合は承認手順を用い、未反映を完了と扱わない。

## 対象外

- 各ゲームのビルド・公開設定とソースの実際の移行。
- ブランチ別に複数の仮版を公開する機能。
- ゲーム別の正式版・仮版選択UI。
- 共通ライブラリへの isPreview() API の追加。
- 自動フォールバック、仮版未公開専用表示、認証・非公開プレビュー。

## 実装方針と対象ファイル

- .github/workflows/: workflow_call を持つ共通処理と、ポータルの起動用設定。
- scripts/ 等: 必要に応じて共通の公開先計算・成果物検証処理と設定例。
- vite.config.js: 共通処理が指定した公開パスを反映し、ローカルでの既存利用も確認する。
- src/portal/main.js: 分散しているゲーム基準URLの生成を集約し、各取得先とリンクを揃える。
- index.html、ポータルCSS: Preview タグを既存ヘッダーに配置し、モバイル表示も確認する。
- docs/common/: 公開ルール、標準データ、導入・公開手順、共通部参照の文書を整合させる。
- docs/portal/: query による参照切替とタグ、失敗時の既存動作を規定する。
- public/data/update_history.json: 利用者向けの変更を 1.17 単位で記載する。
- tests/: 仕様と実装の責務に応じて参照切替・公開処理の検証を配置する。

## 検証方針

- URL判定・変換、公開先判定などの複雑な処理は、実装前に仕様をテストで定義する。
- query 未指定・on・それ以外と、ポータル自身の正式版・仮版の組合せを確認する。
- 紹介JSON・更新履歴・画像・ロゴ・プレイ先が同じ環境を参照することを確認する。
- 自ゲームへの絶対URL、相対パス、外部リンク、取得失敗、pending、言語切替を確認する。
- Preview タグの表示条件と、言語選択の左に収まることをデスクトップ・モバイルで確認する。
- 共通処理のイベント/ref判定、配置先、正式版と仮版の相互保持、更新競合対策を検証する。
- 全テスト npm.cmd test、正式版と仮版のビルドを実行し、生成物の公開パスを確認する。
- 実装報告には各コマンドと結果、失敗時の調査、オーナー検証と判断を記録する。

## 完了条件と公開後の確認

- 共通ルール・共通処理・ポータルの挙動が一致する。
- 全テストと正式版・仮版ビルドが成功し、公開パスと配置先、相互保持が検証される。
- 6ゲームの移行バックログが追加される。
- 必要なオーナー検証の判断を得る。未回答を担当者判断で保留にしない。
- GitHub Actions 上の実行と公開URL・実機での確認は、ローカルの検証と区別する。
  共通処理の公開前には各ゲームでの実行を完了扱いにしない。
- 公開後に、ポータルの master push による正式版公開、手動の仮版公開、双方の保持、素材・表示・バージョンを確認する。
  マージ前にできない確認の扱いはオーナーの明示判断を得て記録する。
- 各ゲームの公開確認は、後続のゲームごとの移行作業で実施する。
