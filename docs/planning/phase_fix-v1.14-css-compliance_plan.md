# 共通ライブラリとポータルの CSS 規約適合 計画書

- 作業ブランチ: `fix/v1.14-css-compliance`
- 予定バージョン: `1.14.0`。実装フェーズ開始時に更新する。

## 開発範囲

`src/lib/` の全モジュールと共通 CSS を CSS 設計ルールに照らして確認し、クラスの命名・責務、`!important`、インラインスタイルの使用について確認結果を実装報告に記録する。確認済みの不一致は `TutorialManager` の状態クラス `hidden`、`arrow-up`、`arrow-down`。正式なクラスをそれぞれ `state-hidden`、`state-arrow-up`、`state-arrow-down` としてライブラリ仕様書に記載する。ツールチップと矢印の座標を動的に設定する処理は規定の例外に該当する。

ポータルの HTML・CSS・JavaScript も同じ規約で点検する。注目バッジの `is-featured`、更新履歴モーダルの `active`、ヘッダーの `scrolled`、表示アニメーションの `visible` を `state-*` に揃え、対応する CSS セレクタとテストを更新する。カード画像 URL は既存のメタデータから読み込み、生成 HTML の `style` 属性に埋め込まず、画像要素の `src` と CSS のレイアウト指定で従来の表示を再現する。

## 公開インターフェースと互換性

共通 CSS の公開セレクタと、ライブラリがゲーム側 DOM で参照・付与・解除するクラス名を公開インターフェースとして扱う。変更前に利用箇所を調べる。旧クラスは既存ゲーム向けの互換処理に限定し、既存の HTML と CSS で表示・非表示と矢印の向きが機能するようにする。矢印の更新では向きのクラスだけを切り替え、ゲームが付けた他のクラスを保持する。

旧チュートリアルクラスへの依存を GravityFreight、BurstCascade、CanWeBecomeHeroes で確認済み。公開インターフェースの変更によりゲーム側の対応が必要になる場合は、影響を受ける各ゲームの `docs/planning/backlog.md` に「共通ライブラリの仕様変更に対応する」を追加し、変更前後のクラス名、修正箇所、確認すべき動作を記載する。互換処理で従来の動作を維持できる場合は、移行が必須になった時点で起票する。

ポータルの状態クラスは内部の表示制御に使う。`project_info.json` と `update_history.json` は現行の形式と読み込み方を維持し、注目期限の判定とカードの並び順を維持する。

## 対象外

ゲーム側の HTML・CSS の移行実装、ゲームが公開する JSON の形式・内容の変更、チュートリアル進行仕様の変更。

## 完了条件とテスト方針

- 共通ライブラリとポータルの点検結果、修正した不一致、公開インターフェースへの影響を実装報告に記録する。
- 新旧それぞれの HTML・CSS 構成で、マスクとツールチップの表示・非表示、矢印の両方向への切り替え、利用側クラスの保持を確認する。手動制御と管理制御の既存挙動を維持し、対象テストで閉じる操作とリセットも確認する。
- ゲーム側の変更が必要な場合は、影響を受ける各ゲームのバックログへの起票を確認する。
- ポータルでは、注目期限の判定とカードの順序、モーダルの開閉と履歴表示、スクロール時の状態切り替え、カード画像の表示を確認する。
- `npm.cmd test -- tests/implementation/lib/core/tutorialManager.test.js tests/implementation/portal/main.test.js`、`npm.cmd test`、`npm.cmd run build` の結果を実装報告に記録する。オーナー検証が必要な場合は、実装フェーズで確認項目を提示する。
