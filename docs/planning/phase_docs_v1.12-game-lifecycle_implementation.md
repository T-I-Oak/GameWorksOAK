## 構成照合と公開予告の運用

以下をローカルの既存構成と照合した。外部サービスの現時点の設定や実際の公開状態は今回の確認対象に含めていない。

- `src/portal/main.js`はゲームIDから標準URLを組み立て、紹介JSON・素材・更新履歴を取得する。
- `public/data/project_list.json`は`id`と`title`を保持し、別の予告用取得先は設定できない。
- `button.type: pending`はポータルのボタン無効化であり、ゲームURLの直接アクセスを制限しない。
- 隣接するGravityFreightの`vite.config.js`、`package.json`、`.github/workflows/deploy.yml`を参照した。既存CIは共通部checkout・隣接リンク後にゲームをビルドし、`dist`全体を公開する。個別のビルド詳細を共通必須設定として転記していない。
- CanWeBecomeHeroesの紹介JSONとCIを確認した。公開予定バッジとpendingボタンの組合せが公開予告であるとオーナーに確認済み。予告用成果物とゲーム本体の分離は要件にしない。
- 公開予定時期は公開すると判定した時点でオーナーと調整し、紹介JSONへ反映する。ポータル一覧登録は基本的にオーナーが対応し、ゲーム担当は修正せず完了を確認する。

## オーナー検証

利用者が操作する機能の変更はなく、追加の操作検証項目は設けていない。
オーナーによる文書確認で受けた指摘を反映し、2026-10-21に「私の確認は以上です」との連絡を受けた。最終確認として全62テスト・本番ビルド・相対リンク68件の検証を再実行し、すべて成功した。
公開準備の責務と完了条件はオーナーの説明を反映し、予定時期の調整・JSONへの反映・ポータル一覧登録の完了確認として記載した。
未回答の操作検証を保留としてバックログへ移すことはしていない。

## オーナーフィードバックへの対応

- 「公開予告は公開準備の作業の一環」との指摘を反映し、全体の流れで並列に読める「公開準備と予告公開」を「公開準備」へ修正した。
- 公開準備文書で包含関係を明記し、公開方法の確認も公開準備の中の作業として統一した。
- 環境構築前にオーナーが配置したファイルの保全手順を追加した。未追跡・ignore対象も確認し、雛形生成・ビルド等の上書きや削除を避け、必要な変更・移動・置換は対象と理由を示して合意後に行う。完了条件にも保全確認を追加した。
- 公開予定時期の調整と紹介JSONへの反映、オーナーによる一覧登録とゲーム担当による完了確認を明記した。公開予告に本体の分離が必要という追加要件は除いた。ゲーム側JSONやポータル一覧の実際の更新は今回行っていない。
- オーナーによる文書確認は終了した。最終の検証結果に基づき終了草案を再提示する。引継ぎ書の保存・コミットは草案承認後に行う。
- 初回ゲーム公開は公開指示とv1へのMajor更新指示の両方を開始条件とし、v0のままの公開を禁止した。公開時のバッジは原則「○月○日 vX.X公開！」とし、実際の公開日・Major.Minorを記載する。異なるバッジはオーナーの明示指示がある場合に適用する。
- 公開時のバッジ強調期間はオーナーへ確認し、合意した終了日を`badge.featuredUntil`へ設定する。強調しない指示の場合は省略し、未回答を省略の合意と扱わない。
